# 字幕校对台 · Live Subtitle QC Console

面向直播运营团队的字幕校对工作台。现场字幕事件持续推送，网络抖动会造成**乱序、重复**，机器修订还可能**覆盖人工已确认的内容**——本工作台把这些情况全部可视化，并把最终裁决权交给运营人员。

全部数据在浏览器本地模拟，不依赖任何后端服务。

## 功能一览

- **三栏直播工作台**：直播预览（ON AIR 监视器 + 待播队列）、字幕时间线、事件流同屏呈现
- **乱序补齐**：字幕按序号排列，缺失片段留下明显空位（斜纹 + 虚线框 + 文字说明）；晚到片段自动补回
- **重复去重**：同一事件 ID 重发、或不同事件内容完全相同，都只记录日志，绝不生成第二条字幕
- **版本更新**：未锁定片段收到更高版本机器修订时直接应用，过期版本被忽略
- **锁定冲突**：人工修改并锁定后，机器修订不再静默覆盖，转为待裁决冲突——由运营选择「保留人工版本」或「接受机器修订」
- **批次复核**：直播结束后机器一次补发多条修订时，按补发组生成**稳定批次**，收齐后整批进入复核面板：
  - 条目实时分类为 **新增 / 改写 / 锁定冲突 / 无变化**，展示“当前时间线 vs 批次机器版本”
  - **人工锁定内容默认排除**，运营在时间线明确解锁后才自动进入勾选；无变化条目永不应用
  - 支持**整批接受、逐条勾选/排除、接受勾选并排除其余**三种收尾；部分接受后可继续处理
  - 每次接受都可**撤销 / 重做**（LIFO，重做带版本护栏：撤销后人工改过则拒绝静默重做）
  - **批次重复到达 / 事件重发不会重复应用**（事件 ID 去重 + 已完成批次整批重发忽略）
  - **复核进行中同批次片段晚到**：批次标记「已过期」并重新计算，针对旧内容的勾选作废，绝不静默套用旧选择
  - 批次外的常规直播流在复核期间照常落位，互不阻塞
  - **刷新恢复**：复核现场（缓冲、勾选、部分接受结果、撤销栈、已完成批次审计）持久化到 localStorage，刷新后无损继续
- **可稳定重放的“网络抖动 + 直播后补发”场景**：内置 `101 → 103 → 103(重复) → 102(晚到) → 102 的机器修订 v2`，直播后 +13s 一次补发 5 条组成复核批次（新增/改写/无变化/重复/锁定冲突），+20s 同批次 #105 晚到触发过期重算；支持播放 / 暂停 / 单步 / 0.5–4× 倍速 / 重放；每次重放从干净状态开始，相同操作必然得到相同结果
- **不只靠颜色区分状态**：播出中、缺口、重复、冲突、锁定、批次复核中均有图标 + 文字徽标（缺口另有斜纹图案），色盲友好

## 运行方式

要求 Node.js ≥ 18。

```bash
npm install       # 安装依赖
npm run dev       # 开发模式（默认 http://localhost:5173）
npm test          # 运行自动化测试（Vitest，39 个用例）
npm run build     # 生产构建（tsc 类型检查 + vite 打包到 dist/）
npm run preview   # 预览生产构建产物
```

## 快速体验：复现一次“锁定冲突”

1. 点击底部「▶ 播放」，观察 `#101` 到达、`#103` 乱序到达留下 `#102` 缺口、重复 `#103` 被去重、`#102` 晚到自动补回；
2. 在 `#102` 补齐后（+4.5s）、修订到达前（+10s）点击「⏸ 暂停」；
3. 在时间线上「✏️ 修改」`#102` 的文本，然后点击「🔒 锁定」；
4. 点击「▶ 播放」继续，机器修订 v2 到达 → 顶部出现**待裁决冲突**面板；
5. 选择「✋ 保留人工版本」或「🤖 接受机器修订」，观察时间线与事件流的变化；
6. 随时点击「↺ 重放」回到干净状态重新开始；也可以用「⏭ 单步」逐事件精确推进。

## 快速体验：一次“直播后批次复核”

1. 让场景播放到 +13s：机器一次补发 5 条，自动生成批次 `batch-post-live`，顶部出现**批次复核**面板；
2. 查看分类：`#104` 新增、`#101` 改写、`#103` 无变化、`#104` 重发（标“重复到达”）、若提前锁定 `#102` 则其修订显示为锁定冲突且默认排除；
3. 用复选框逐条排除，或直接「✓✓ 整批接受」；也可「✓ 接受所选」做部分接受，再继续处理剩余条目；
4. +20s 同批次 `#105` 晚到 → 面板出现红色过期横幅，旧勾选作废、列表重算，需要重新选择；
5. 接受后点「↩ 撤销」时间线逐字还原，「↪ 重做」重新应用（撤销后若人工改过相关字幕，重做会被拒绝）；
6. 复核中途刷新页面，刷新后批次、勾选、部分接受结果与撤销栈原样恢复。

## 架构说明

```
src/
├── types.ts            领域模型（事件 / 片段 / 冲突 / 日志 / 批次 / 状态）
├── consoleReducer.ts   纯函数状态机：去重、补齐、版本裁决、锁定冲突、批次复核、重置
├── batch.ts            批次纯函数：条目归并、分类（新增/改写/冲突/无变化）、选择重算
├── storage.ts          刷新恢复：可注入 Storage 的序列化/校验/规范化
├── selectors.ts        派生数据：缺口、当前播出、待播队列、批次视图等
├── scenario.ts         内置“网络抖动 + 直播后补发”场景脚本（逻辑时间戳，确定性数据）
├── player.ts           播放器：按分组投递批次边界，支持播放/暂停/单步/倍速/重放，调度器与时钟可注入
├── useSubtitleConsole.ts  React 装配层（useReducer + Player 单例 + localStorage 持久化）
├── components/         界面组件（预览 / 时间线 / 事件流 / 冲突面板 / 批次复核面板 / 播放控制）
└── __tests__/          Vitest 测试（console / player / batch / storage）
```

**确定性设计**（“相同操作 → 相同结果”的保证）：

- reducer 是纯函数，不读时钟、不含随机数；事件自带逻辑时间戳；
- 播放器的调度器与时钟均可注入，测试中用手动时钟同步驱动；
- 「重放」= `reset` 动作（返回全新初始状态）+ 从头调度同一场景脚本。

**关键规则**：

| 情况 | 行为 |
| --- | --- |
| 相同事件 ID 再次到达 | 记「重复」日志，状态不变 |
| 同序号同版本同文本 | 记「重复」日志，状态不变 |
| 更低版本到达 | 记「过期」日志，状态不变 |
| 更高版本 + 未锁定 | 直接应用修订（若覆盖了未锁定的人工修改，会在日志中注明） |
| 更高版本 + 已锁定 | 登记待裁决冲突，人工内容原样保留 |
| 裁决「保留人工」 | 丢弃该机器修订，片段维持锁定 |
| 裁决「接受机器」 | 应用修订内容并解除锁定，片段交还机器流 |
| 补发批次事件到达 | 不落时间线，进入批次缓冲，收齐后整批进入复核 |
| 批次条目分类 | 无片段=新增；版本更高且文本不同=改写；锁定片段=冲突；版本不高于当前或文本相同=无变化 |
| 锁定片段进入批次 | 默认排除、不可勾选；明确解锁后自动纳入；整批接受也不会覆盖它 |
| 复核中同批次又有更新 | 批次标记过期、列表重算；旧内容对应勾选作废，需重新选择 |
| 批次/事件重复到达 | 事件 ID 去重；已完成批次整批重发直接忽略，绝不重复应用 |
| 接受后撤销 / 重做 | 按接受步骤 LIFO 还原应用前快照（新增删除、改写还原）；重做有版本护栏 |
| 刷新页面 | 从 localStorage 无损恢复批次、勾选、部分接受结果与撤销栈 |

**播出规则**：当前播出字幕是从最小序号起连续完整的最长前缀末尾——缺口之后的片段即使已到达也只进入待播队列，直到缺口补齐。

## 自动化测试

`src/__tests__/` 共 39 个用例，覆盖需求要求的全部场景：

- **乱序补齐**：缺口出现/消失、播出序号不越过缺口、补齐日志
- **重复去重**：事件 ID 级去重、内容级去重，均不产生第二条字幕
- **版本更新**：未锁定片段应用修订、过期版本被忽略
- **锁定冲突**：不静默覆盖、锁定时禁止编辑、「保留人工」与「接受机器」两种裁决
- **批次复核**（`batch.test.ts`，19 例）：
  - 批次收集与四分类、默认勾选只含新增/改写
  - **重复批次**：begin/end 重发幂等、批次内重发不重复、整批完成后重发忽略
  - **晚到片段**：复核中晚到标记过期、旧勾选作废、接受的是新内容；缓冲晚到新增接受后补齐缺口
  - **锁定冲突**：默认排除不可勾选、解锁后自动纳入、整批接受不覆盖锁定、显式排除才可收尾
  - **部分接受 / 整批接受**：只应用勾选、剩余继续复核、无变化不写时间线、人工编辑后移出勾选
  - **撤销 / 重做**：时间线与批次状态同步还原、LIFO 逐步撤销、人工改动后重做护栏拒绝、新接受清空重做栈
  - 批次与常规流共存、批次内过期版本忽略
- **刷新恢复**（`storage.test.ts`，4 例）：待复核/部分接受/撤销栈无损恢复、open 批次提升 pending、完成批次审计恢复、坏数据安全回退
- **无残留重放**：reset 后与初始状态逐位相等；同操作序列重放结果一致；播放器两轮完整播放终态一致
- **播放器行为**：按时间表投递、批次边界投递、暂停结算剩余时间、倍速重排程、单步与播放混用
